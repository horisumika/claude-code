# クラウドの Claude から業務システムを触れるようにする

「Mac の Claude Code の手元にしかコードが無い」状態を解消し、**ブラウザ／スマホから使うクラウドの Claude でも同じシステムを読み書きできる**ようにするための手順です。

やることは一言でいうと **「Mac にあるコードを GitHub の非公開リポジトリに置く」** だけです。GitHub に置けば、クラウドの Claude がそこから取ってきて作業できます。

---

## 現在の状況（2026-08-18 時点）

| システム | GitHub | クラウドの Claude から | 状態 |
|---|---|---|---|
| 業務管理システム（hori-office-system） | `horisumika/hori-office-system-clean`（非公開） | **触れる** | 接続・ビルド確認まで完了 |
| 告訴状作成システム（line-reply-admin） | まだ無い | 触れない | 下の手順で GitHub に上げれば触れるようになります |

### 業務管理システムでできること・できないこと

| | クラウドの Claude | Mac の Claude Code |
|---|---|---|
| コードを読む・直す | ○ | ○ |
| ビルドして壊れていないか確認 | ○（確認済み） | ○ |
| 実際のデータで動かす | ×（本番DBに繋がないため） | ○ |
| Vercel へ本番デプロイ | ×（Vercel のログイン情報がクラウド側に無い） | ○ |

つまり **「改修はクラウドでもできる。本番反映は Mac から」** という分担になります。
クラウド側で直した内容は GitHub 経由で Mac に降ろせるので、二重作業にはなりません。

---

## 告訴状作成システムを GitHub に上げる手順

> 下の「===」で囲まれた中を、まるごとコピーして **Mac の Claude Code** に貼り付けてください。

```
=======================================================================
告訴状作成システム（Vercel プロジェクト: line-reply-admin）のソースコードを、
GitHub の「非公開」リポジトリに上げてほしい。目的は、クラウド版の Claude
からも同じコードを読み書きできるようにすること。

【いちばん大事な前提：個人情報と鍵を絶対に上げない】
業務管理システムを上げたときと同じ考え方で、「公開しても安全な状態」に
してから push すること。具体的には push の前に必ず次を確認する。

1. .gitignore に以下が入っていること（無ければ追加する）
   - .env / .env.* などの環境変数ファイルすべて
   - *.db / prisma/dev.db などのローカル DB ファイル
   - バックアップ・エクスポート出力のフォルダ
   - 実在の依頼者名・警察担当官名を含むスクリプトやドキュメント
2. `git status` で、上げようとしているファイル一覧を目視確認する。
   依頼者の実名・住所・電話番号・事件の内容が入ったファイルが
   1つでも混ざっていたら、.gitignore に足して除外する。
3. ソースコード中に API キー・パスワード・トークンが直書きされていないか
   検索して確認する（例: `grep -rniE "sk-|api[_-]?key|password|secret|token" --exclude-dir=node_modules .`）。
   見つかったら環境変数に切り出してから push する。
4. 過去のコミット履歴にも個人情報や鍵が残っている可能性がある。
   確信が持てない場合は、履歴を引き継がず
   「今の状態だけの新規リポジトリ」として上げること
   （業務管理システムの hori-office-system-clean と同じやり方）。

【手順】
1. 上のチェックを済ませる。
2. GitHub に非公開（private）リポジトリを作る。
   名前は `line-reply-admin-clean` を推奨（clean = 個人情報を除いた版、の意味）。
   オーナーは horisumika。
3. 現状のコードを初期コミットとして push する。
4. push が終わったら、リポジトリ名と URL を教えてほしい。
5. あわせて、README に「必要な環境変数の名前だけ」を一覧で書いておく
   （値は書かない）。クラウド側で改修するときに何が要るか分かるようにするため。

【注意】
- Vercel の設定・環境変数の実値は GitHub には上げない。本番の値は
  これまでどおり Vercel 側にだけ置いておく。
- 認証・アクセス制限のロジックは今回いじらない。上げるだけ。
=======================================================================
```

push が終わったら、その **リポジトリ名をクラウドの Claude に伝えてください**。こちら側で接続して、業務管理システムと同じように読み書きできる状態にします。

## クラウド側で毎回やること（参考・Claude 用のメモ）

新しいクラウドセッションから業務管理システムを触るときの手順です。Claude が自動で行うので、澄香さんが覚える必要はありません。

1. リポジトリをセッションに接続する（`add_repo` で `horisumika/hori-office-system-clean`）
2. `git clone --depth 1 https://github.com/horisumika/hori-office-system-clean /workspace/hori-office-system-clean`
3. `npm install`（Prisma Client の生成まで自動で走る）
4. 壊れていないかの確認は
   `DATABASE_URL="postgresql://user:pass@localhost:5432/db" npx next build`
   （実データには繋がない、ダミーの接続文字列でビルドだけ通す）

### 技術メモ

- Next.js 16 / React 19 / Prisma 6（PostgreSQL・本番は Neon）/ NextAuth v5 / Tailwind 4
- Vercel Cron が4本（朝・夕の通知、追客更新、カレンダー取込）
- 本番に必要な環境変数は `DATABASE_URL` のほか、LINE WORKS 連携・Google OAuth・
  Gmail 送信・Anthropic API・Vercel Blob 等で 30 個以上。値はすべて Vercel 側にあり、
  GitHub には含まれていません。
