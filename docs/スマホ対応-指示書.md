# スマホ対応 指示書（Mac 側の Claude Code に貼るだけ）

このファイルの中の **「貼り付け用プロンプト」** を、Mac 上でいつもシステムを触っている Claude Code にコピー＆ペーストしてください。
2つのシステムがあるので、プロンプトも2つに分けています。片方ずつでも、続けて両方でも構いません。

---

## ① 業務管理システム（hori-office-system）用

> 下の「===」で囲まれた中を、まるごとコピーして Claude Code に貼り付けてください。

```
=======================================================================
業務管理システム（Vercel プロジェクト: hori-office-system / 本番 URL:
hori-office-system.vercel.app）を、スマートフォンでも快適に操作できるよう
レスポンシブ対応してほしい。ログイン認証・アクセス制限などの動作ロジック
は一切変えず、「表示・レイアウト」だけを改善すること。

【全ページ共通でやること】
1. 全ページの <head> に
   <meta name="viewport" content="width=device-width, initial-scale=1">
   が入っているか確認し、無ければ追加する。
2. 横スクロールを撲滅する。固定幅（px 指定の width）を max-width:100% /
   % / rem に置き換え、画面幅 375px・390px（iPhone 実機幅）で横に
   はみ出す要素をすべて潰す。
3. 一覧テーブルは、モバイル（幅 640px 未満）では「カード表示」に切り替える。
   各行を縦積みのカードにして、主要項目（種別・日付・金額・ステータス等）を
   見出し付きで表示する。カード化が難しい表は、横スクロール専用の枠
   （overflow-x:auto）の中に閉じ込め、ページ本体は横スクロールさせない。
4. ボタン・リンクのタップ領域を最低 44×44px 確保し、間隔を空ける。
5. 本文・入力欄のフォントサイズを 16px 以上にする（iOS で入力時に勝手に
   ズームするのを防ぐ効果もある）。
6. ナビゲーションは小画面ではハンバーガーメニューか縦積みにする。
7. 固定ヘッダー／フッターが入力欄やボタンを隠さないようにする。

【画面ごとの具体対応】
- ログイン画面：1カラム中央寄せ。メール・パスワード入力欄を幅100%、
  16px 以上。キーボード表示時にボタンが隠れないように。
- 「今日やること」ページ：項目をカードで縦積み。
- 「単発業務の登録」フォーム：種別セレクト・実施日・備考・登録ボタンを
  縦1カラムに。実施日は <input type="date"> にしてモバイルのネイティブ
  日付ピッカーを使えるようにする。
- 請求書ページ（/staff/invoice）：
  ・氏名・住所・電話・銀行口座の入力欄をモバイルで押しやすく（幅100%）。
  ・明細テーブルは画面表示ではカード化 or 横スクロール枠に収める。
  ・ただし印刷（@media print）では従来のA4テーブルレイアウトを維持し、
    iPhone Safari の「共有→プリント→PDF保存」でレイアウトが崩れない
    ように print 用 CSS（@page 含む）を整える。
- 「今月稼働分（翌月払い）」の金額表示を、モバイルで大きく見やすく。

【進め方・安全面】
- 認証情報や依頼者の個人情報を、コードやコミットに絶対に埋め込まない。
- 1画面ずつ確認しつつ、修正はまとめてから1回でビルド＆デプロイする。
- デプロイ前に必ず、そのプロジェクトのディレクトリに cd してから
  `npx next build` を実行し、エラーが無いことを確認する。
- 実機幅 375px / 390px で表示確認してからデプロイする。
- デプロイは既存の手順どおり（例: `cd <プロジェクトのパス> &&
  npx next build && npx vercel --yes --prod`）。
=======================================================================
```

## ② 告訴状作成システム（line-reply-admin の告訴状部分）用

> 下の「===」で囲まれた中を、まるごとコピーして Claude Code に貼り付けてください。

```
=======================================================================
告訴状作成システム（Vercel プロジェクト: line-reply-admin / 対象画面:
line-reply-admin.vercel.app/admin/complaints 以下）を、スマートフォンでも
快適に操作できるようレスポンシブ対応してほしい。今回は /admin/complaints
配下（告訴状関連）だけが対象。ログイン認証・アクセス制限（告訴状関連以外は
表示しない等）の動作ロジックは一切変えず、「表示・レイアウト」だけを改善する。

【全ページ共通でやること】
1. viewport メタタグ（width=device-width, initial-scale=1）を全ページで確認・追加。
2. 横スクロールを撲滅（固定 px 幅を max-width:100% / % / rem に）。
   画面幅 375px・390px ではみ出す要素をすべて潰す。
3. タップ領域は最低 44×44px、本文・入力欄フォントは 16px 以上。
4. ナビは小画面でハンバーガー／縦積みに。

【画面ごとの具体対応】
- 告訴状一覧（/admin/complaints）：
  一覧テーブルをモバイルではカード表示に。各カードに
  「依頼者名・ステータス・最終更新日」を主表示し、ステータスは色付き
  バッジで見せる。カードをタップで詳細へ。
- 新規告訴状作成フォーム：
  依頼者情報／事実関係／媒体／証拠などの長大な入力項目を、モバイルでは
  セクションごとのアコーディオン（折りたたみ）にして扱いやすくする。
  事実関係などの長文 textarea は幅100%・十分な高さ・16px 以上。
- AI支援ボタン・警察タスク（TODO）・ステータス変更ボタンを、親指で
  押しやすい大きさ・配置にする。
- ステータスの流れ（受任前→ヒアリング中→書類作成中→澄香チェック待ち→
  警察電話済→郵送済→受理済）の横長表示は、小画面では縦並び、または
  横スクロール枠に収める。
- 告訴状のプレビュー／印刷がある場合は、業務管理システムの請求書と同様に
  @media print を整え、PDF 保存でレイアウトが崩れないようにする。

【進め方・安全面】
- 認証情報や依頼者の個人情報を、コードやコミットに絶対に埋め込まない。
- アクセス制限（補助者は告訴状関連のみ表示等）の挙動を壊さないこと。
- 1画面ずつ確認しつつ、修正はまとめて1回でビルド＆デプロイ。
- デプロイ前に、そのプロジェクトのディレクトリに cd してから
  `npx next build` を実行しエラーが無いことを確認。
- 実機幅 375px / 390px で確認してからデプロイ（既存の手順どおり）。
=======================================================================
```

## 補足：今すぐできること

上の改修をしなくても、両システムは Web 上にあるので **今この瞬間からスマホのブラウザで開いてログインする**こと自体は可能です（URL は README 参照）。
今回の作業は「小さい画面でも見やすく・押しやすくする（快適に操作できるようにする）」ための改善です。

## 用語のかんたん説明

- **レスポンシブ対応**：PC でもスマホでも、画面サイズに合わせて自動でレイアウトが変わるようにすること。
- **ビルド／デプロイ**：作ったコードを本番サイトに反映させる作業。Claude Code が自動で行います。
- **print CSS（@media print）**：印刷・PDF 保存したときだけ適用される見た目の設定。請求書・告訴状の PDF が崩れないために必要。
